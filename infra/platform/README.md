# Platform Droplet

One DigitalOcean Droplet runs every monorepo app in Docker Compose, with one Postgres shared between them (a database per app). Public sites are served on the internet through Caddy. Private apps are reachable only from your devices over Tailscale. Backups go to Spaces with pgBackRest, and a weekly restore test on a short-lived Droplet proves they restore.

```
                         internet                          your tailnet (phone, laptop)
                            │ 80/443                                │
┌───────────────────────────┼─────── platform Droplet ──────────────┼─────────────────────┐
│                      ┌────▼────┐                           ┌──────▼───────┐             │
│                      │  caddy  │ public network            │ ts-barnbooks │ barnbooks   │
│                      └────┬────┘                           └──────┬───────┘ network     │
│                      ┌────▼──────┐                         ┌──────▼────────┐            │
│                      │ farm-site │                         │ barnbooks-web │──/api──┐   │
│                      └───────────┘                         └───────────────┘        │   │
│                                                            ┌────────────────┐       │   │
│   backend network (no published ports)  ┌──────────────────│ barnbooks-api  │◄──────┘   │
│   ┌───────────────────────┐             │                  └────────────────┘           │
│   │ db: Postgres 18       │◄────────────┘                                               │
│   │ + pgBackRest          │ data on a Block Storage Volume (/mnt/pgdata)                │
│   └──────────┬────────────┘                                                             │
└──────────────┼──────────────────────────────────────────────────────────────────────────┘
               │ WAL + weekly full / daily diff (encrypted)
               ▼
   Spaces: backup bucket (another region, versioned) ──read-only──► weekly restore-test Droplet
   Spaces: dumps bucket  ◄── sanitized pg_dump of each database ──┘  (created and destroyed by CI)
```

## Setting up

The DigitalOcean resources, the GitHub settings the restore test needs, and `/opt/platform/.env` are all created by OpenTofu in `infra/terraform/`. The state file is local and encrypted.

**Once, by hand** (these can't be created through an API, or are needed to run OpenTofu):

| What | Where | Used as |
|---|---|---|
| API token, full access | DO → API | `DIGITALOCEAN_TOKEN` env var |
| Spaces key with full access | DO → Spaces Keys | `SPACES_ACCESS_KEY_ID` / `SPACES_SECRET_ACCESS_KEY` env vars (creates the buckets) |
| API token with custom scopes `droplet:create`, `droplet:read`, `droplet:delete`, `ssh_key:read`, `tag:create`, `tag:read` (all six) | DO → API | `restore_test_do_token` in `terraform.tfvars` |
| Fine-grained token on this repo: Administration, Secrets, Variables (write) | GitHub → Settings → Developer settings | `GITHUB_TOKEN` env var |
| State passphrase | your password manager | `TF_VAR_state_passphrase` env var |
| Tailscale auth key for the host (not ephemeral) | Tailscale admin → Settings → Keys | `ts_authkey_host` (optional: or run `sudo tailscale up --ssh --hostname platform` on the Droplet later) |
| Tailscale auth key per **private app** (not ephemeral), and **MagicDNS + HTTPS Certificates** enabled in the tailnet's DNS settings | Tailscale admin | `ts_authkey_apps = { barnbooks = "tskey-auth-…" }`, **required**: an app's sidecar can't use a login link (see the gotchas) |
| Healthchecks.io: "platform backups" (period 1h, grace 2h) and "restore test" (period 1 week, grace 1 day) | healthchecks.io | `hc_backup_url`, `hc_restore_url` (optional) |

**Create everything**

```sh
cd infra/terraform
cp terraform.tfvars.example terraform.tfvars    # fill it in
export TF_VAR_state_passphrase=... DIGITALOCEAN_TOKEN=... GITHUB_TOKEN=... \
       SPACES_ACCESS_KEY_ID=... SPACES_SECRET_ACCESS_KEY=...
tofu init
tofu plan          # review it
tofu apply
```

This creates:
- **DigitalOcean:** the VPC, the Droplet (no `user_data`), the unformatted Block Volume, the Cloud Firewall, the backup bucket (another region, versioned) and the dumps bucket (expiring), three Spaces keys scoped to one bucket each, and disk/CPU/memory alerts (to `alert_email` and/or `alert_slack`, if set).
- **GitHub:** the read-only deploy key, and the restore-test workflow's secrets and variables.
- **Locally:** `out/platform.env` and `out/deploy_key`.

The volume and the backup bucket refuse to be destroyed by OpenTofu.

**Then**

1. Create the DNS records from `tofu output dns_records_to_create` at your DNS host.
2. `./bootstrap.sh` copies `out/platform.env` and the deploy key to the Droplet over SSH, then runs `provision.sh` as root. Secrets never go in `user_data`, which anything on the Droplet can read.
3. Check `ssh <admin_user>@<droplet_ip>` works: provision.sh disables root login.
4. Deploy: `ssh <admin_user>@<droplet_ip> sudo /opt/platform/repo/infra/platform/deploy.sh`.
5. In the Tailscale admin console, **disable key expiry** on the `platform` machine and each app's machine (e.g. `barnbooks`). Otherwise they need logging in again after about six months.
6. Once `ssh <admin_user>@platform.<your-tailnet>.ts.net` works, set `admin_cidrs = []` and `tofu apply` to close port 22. From then on, reach the Droplet over Tailscale, including for `./bootstrap.sh --admin platform.<your-tailnet>.ts.net`.

barnbooks is then at `https://barnbooks.<your-tailnet>.ts.net` on your devices, and farm-site at `farm_site_domain`. The first request to a private app can take 10–20 seconds while its certificate is issued.

**Changing settings later:** edit `terraform.tfvars`, `tofu apply`, then `./bootstrap.sh --admin <host>` to copy the new `.env` and re-run provision.sh. Running containers keep their old settings until recreated: run `sudo platform-compose up -d` on the Droplet, which recreates only the services whose settings changed.

**Keep safe:**
- the state passphrase, and a backup of `terraform.tfstate`: it holds every generated secret, encrypted;
- `PGBACKREST_CIPHER_PASS`, which is in the state and in `out/platform.env`. Store a copy in your password manager too: without it the backups can't be decrypted.

### First-run gotchas

Problems hit on the first real apply, and their fixes. The variable checks catch some of them before anything is created.

- **Region has no capacity** (`Size is not available in this region`). New accounts often can't create Droplets in New York. List what a region currently offers your account:
  ```sh
  doctl compute size list -o json | jq -r '.[] | select(.available and (.regions|index("tor1"))) | .slug'
  ```
  An empty result means none.
- **Moving regions after a failed first apply:**
  - **"Can not delete default VPCs".** The first VPC created in a region becomes that region's default and can't be deleted. Rename it, stop managing it, and pick a new range:
    ```sh
    doctl vpcs update <id> --name <region>-default
    tofu state rm digitalocean_vpc.platform
    ```
    Then set a different `vpc_ip_range`.
  - **The volume's `prevent_destroy` blocks the move.** If it has never held data, comment out `prevent_destroy` on `digitalocean_volume.pgdata`, apply, then `git checkout droplet.tf`.
- **`email is not verified`.** Alert emails must belong to a verified DigitalOcean user: your login email, or a team member who has accepted an invitation. A team contact email isn't enough. Use `alert_slack` instead, or leave both empty for now.
- **SSH times out.** `admin_cidrs` must contain your current IP (`curl -4 ifconfig.me`). Home IPs change, so update it and re-apply when SSH stops working.
- **"Failed to request input from user for variable var.state_passphrase".** Every `tofu` command reads the encrypted state, including `tofu state rm`. Export the passphrase in that terminal:
  ```sh
  read -rs TF_VAR_state_passphrase && export TF_VAR_state_passphrase
  ```
- **GitHub `401 Bad credentials` or `403 Resource not accessible`.**
  - `GITHUB_TOKEN` must be exported in the same shell.
  - With no `GITHUB_TOKEN`, the provider falls back to the `gh` CLI's token, so `unset GH_TOKEN` if that one is stale.
  - The token needs Administration, Secrets and Variables (read and write) on this repository.
- **Restore test fails at "Create Droplet" with `You are missing the required permissions …`.** The restore-test token needs all of `droplet:create`, `droplet:read`, `droplet:delete`, `ssh_key:read`, `tag:create`, `tag:read`. Create a new token with them, set `restore_test_do_token`, and `tofu apply` (this only updates the `DO_TOKEN` Actions secret). Then re-run the workflow.
- **A private app's Tailscale sidecar restarts every minute** (logs: `tailscale up failed: context deadline exceeded`, and a new "To authenticate, visit" link each time). Without `TS_AUTHKEY_<APP>`, the container's login times out after 60 seconds, so a login link is always stale by the time you open it. Set the key in `ts_authkey_apps`, then `tofu apply`, `./bootstrap.sh --admin <host>`, and `sudo platform-compose up -d ts-<app>`. Remove the stale offline machine in the admin console first, or the new one is named `<app>-1`. `deploy.sh` warns about this.
- **`https://<app>.<tailnet>.ts.net` times out**, the logs show `could not connect to local backend server at 127.0.0.1:443`, and `tailscale serve status` says "No serve config". The tailnet has no HTTPS certificates, so the sidecar can't apply its serve config. Enable them (admin console → DNS → HTTPS Certificates), then `sudo platform-compose restart ts-<app>`. Inside the container, the Tailscale CLI is `tailscale --socket=/tmp/tailscaled.sock …`.
- **`stat /opt/platform/.env: permission denied`.** Run `platform-compose` with `sudo`.
- **`terraform.tfvars` holds tokens.** Keep it private: `chmod 600 infra/terraform/terraform.tfvars`.

## Deploying changes

Merge to `main`, then on the Droplet run `sudo /opt/platform/repo/infra/platform/deploy.sh`. It pulls, rebuilds with fresh base images (so Postgres minor releases arrive here), creates any new app databases, runs every `*-migrate` service, and restarts what changed.

## Adding an app

1. A `Dockerfile` for it under `apps/`.
2. Services in `compose.yaml`:
   - **Public:** put it on the `public` network and add a site block to the `Caddyfile`.
   - **Private:** give it its own network and a `ts-<app>` sidecar like `ts-barnbooks`, plus `tailscale/<app>.json`.
3. If it needs a database:
   - add the app to `app_databases` in `terraform.tfvars`, then `tofu apply` and `./bootstrap.sh --admin` (generates its three passwords into `/opt/platform/.env`);
   - give it an `<app>-migrate` service (tools profile) that connects as `<app>_owner`; the app itself connects as `<app>_app` on the `backend` network;
   - add `infra/postgres/sanitize/<app>.sql`, or list the database in `NO_PII_DATABASES` if it holds no personal data. The restore test fails until you do.

## Backups and restores

- Postgres archives WAL continuously, so it can lose at most about 1 minute of data. Full backups run Sundays at 02:00 and diffs daily; the last 4 fulls are kept.
- `check-backup-freshness.sh` runs hourly and alerts when the latest backup is over 26h old, the latest full over 8 days old, or WAL archiving is failing.

Restoring the platform Droplet in place:

```sh
sudo platform-compose stop
sudo platform-compose run --rm --no-deps -u postgres db pgbackrest --stanza=main --delta restore
#   point in time: add  --type=time --target="2026-10-15 12:00:00+00" --target-action=promote
sudo platform-compose up -d
```

Moving to a new Droplet works the same way after `provision.sh` on the new host.

## Restore test

Every Sunday at 06:00 UTC (or on demand from the Actions tab), the workflow creates a small Droplet, which:
1. restores the latest backup using the read-only key;
2. replays WAL with Postgres accepting no connections, then disconnects it from the network;
3. runs `sanitize/<db>.sql` on each database;
4. uploads a `pg_dump` of each to the dumps bucket under `restore-test/<date>-<run id>/`;
5. powers off.

The workflow then destroys the Droplet whatever happened. A failed run alerts through Healthchecks and fails the workflow.

The dumps are what developers should use instead of production data.

## Personal data

`sanitize/barnbooks.sql` replaces vendor names and match texts, bank descriptions, notes, import filenames and account numbers. It keeps dates, amounts and categories, and vendor matching still works on the result.

It refuses to run if any text, JSON or array column in a table isn't on its reviewed list. So when a migration adds a column, add it there: either scrub it or list it as safe.

## Tests

```sh
infra/platform/test/e2e.sh                     # the whole stack locally, with an S3 gateway standing in for Spaces
infra/postgres/test/test-sanitize.sh           # sanitize/barnbooks.sql on a throwaway copy of the dev database
infra/postgres/test/test-backup-freshness.sh   # freshness check against stand-in commands
shellcheck -x infra/postgres/*.sh infra/postgres/test/*.sh infra/platform/*.sh infra/platform/test/*.sh infra/terraform/*.sh
cd infra/terraform && tofu fmt -check -recursive && tofu validate && tofu test   # mocked providers; creates nothing
```

Not covered by these tests:
- **`provision.sh`'s host steps:** Docker and Tailscale installation, the volume, SSH hardening.
- **Tailscale serve**, and Caddy's public certificates.
- **The workflow's Droplet lifecycle**, and real Spaces.
- **A real `tofu apply`** against DigitalOcean and GitHub.

Check these on the first real deploy.

## Not included yet

- A real login for private apps. Tailscale is the only access control.
- PgBouncer, postgres_exporter/Grafana, and DO Monitoring alert policies (the agent is installed; add the alerts in the control panel).
- A standby replica. When an app outgrows the shared Droplet, give it its own: `pg_dump` its database, or restore the whole cluster with pgBackRest.
